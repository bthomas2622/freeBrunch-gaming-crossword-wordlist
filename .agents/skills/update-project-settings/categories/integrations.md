# Integrations

Integrations connect the docs site to third-party services. Each lives under `integrations.<service>` and holds an ID or key copied from that service; anything that must be set up on the service's side follows its own documentation. Set a field to `null` to disconnect.

Every integration is available on every plan. Secrets (Segment key, Intercom secret, Postman client secret, reCAPTCHA secret, Speakeasy key) read as `null` for users who are not team admins.

Related settings elsewhere: Google and Bing site verification are in [SEO](seo.md). ReadMe's own translation features are in [localization](localization.md).

## Analytics

### Connect an analytics tool

Each tool loads on the docs site once its ID is set:

- **Google Analytics:** `integrations.google.analytics`. A `G-` measurement ID uses Google Analytics 4; a legacy `UA-` ID uses Universal Analytics. IDs with any other prefix are rejected.
- **Heap:** `integrations.heap.id`, the Heap app ID.
- **Segment:** `integrations.segment.key`, the Segment write key. If the user proxies Segment through their own domain, set that domain in `integrations.segment.domain`. See [Segment](https://docs.readme.com/main/docs/segment) and [using a custom domain with Segment](https://docs.readme.com/main/docs/segment#using-a-custom-domain-with-segment).
- **Koala:** `integrations.koala.key`, the Koala public key. It starts with `pk_`; other values are rejected.

Heap, Segment, and Intercom values may only contain letters, numbers, and dashes.

## Support widgets

### Add the Intercom messenger

Set `integrations.intercom.app_id` to the Intercom app ID. The messenger needs the user's Intercom workspace to have the Acquire and Support plans. See [Intercom](https://docs.readme.com/main/docs/intercom#section-which-plans-are-supported).

To turn on Intercom identity verification, set `integrations.intercom.secure_mode.key` to the Intercom identity verification secret. ReadMe then identifies readers by a unique ID; set `integrations.intercom.secure_mode.email_only` to `true` to identify them by email instead, which matches existing Intercom contacts better but is less secure.

### Add the Zendesk widget

Set `integrations.zendesk.subdomain` to the user's Zendesk subdomain.

## Other integrations

### Load an Adobe Fonts kit

Set `integrations.typekit.key` to the Adobe Fonts (Typekit) kit ID, then choose the kit's fonts in typography (see [appearance](appearance.md)).

### Add the Localize.js widget

Set `integrations.localize.key` to the Localize.js project key. Localize.js translates the site in the browser and is independent of ReadMe's [localization](localization.md) settings.

### Protect forms with reCAPTCHA

Set `integrations.recaptcha.site_key` and `integrations.recaptcha.secret_key` from a Google reCAPTCHA invisible v2 site. ReadMe uses it to stop spam in community forums. See [reCAPTCHA](https://docs.readme.com/main/docs/recaptcha).

### Store Postman credentials

The Postman integration syncs the project's API definitions to a Postman workspace as collections:

- `integrations.postman.key`: a key ReadMe shares with Postman. When it is empty, generate a random UUID; the user pastes it into Postman's API Key field.
- `integrations.postman.client_id` and `integrations.postman.client_secret`: copied from Postman.

`integrations.postman.is_connected` (read-only) turns `true` once the connection is made, which happens in the dashboard (see Web-only).

### Connect Speakeasy

`integrations.speakeasy.key` and `integrations.speakeasy.spec_url` connect Speakeasy for SDK code samples. They only take effect once ReadMe has turned on external SDK snippets (`reference.sdk_snippets.external` is not `disabled`; see [API reference](api-reference.md)). Users who want it should contact support@readme.io.

### Web-only

Send the user to the dashboard for these:

- **Connect Postman:** after the credentials are stored, the "Connect to Postman" button at `#/settings/integrations`.
- **Slack and Microsoft Teams notifications:** connected at `#/settings/integrations`. See [Slack](https://docs.readme.com/docs/slack).
- **AWS API Gateway API keys:** personalized docs that issue readers API keys from an API Gateway usage plan. The setup checks the IAM role and registers a login webhook, which only the dashboard does, at `#/settings/personalized-docs`. `integrations.aws.readme_webhook_login` shows the stored role, region, and usage plan; `external_id` is generated by ReadMe and cannot be set. See [personalized docs](https://docs.readme.com/main/docs/personalized-docs).
